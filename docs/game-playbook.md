# Game playbook (SlideForge)

Source of truth for **how each format plays** and what the engine is aiming for:

- External audit: [`Games-Fullscreen-Mechanics-Audit.md`](/Users/m.martin/Desktop/Games-Fullscreen-Mechanics-Audit.md)
- Runtime copy used by the app: [`js/playbook.js`](../js/playbook.js)

Each catalogue format carries:

- **Aim** — pedagogical purpose  
- **How to play** — numbered teacher-facing steps  
- **Phases / timer / players / scoring** — engine summary from the audit  
- **Judgement** — `auto` | `teacher` | `discuss`  
- **Demo kind** — how **Try demo** rehearses it (`board`, `paper`, `class`, `judge`, `discuss`)

The playbook is shown in:

1. **Browse formats** — first how-to step on each card  
2. **Quiz studio inspector** — full How to play + engine box  
3. **Try demo** — board engines in the preview; other formats open a SAMPLE rehearsal with how-to notes on the rail  

Building a missing full board engine still follows [`game-adaptation.md`](game-adaptation.md). The playbook tells you *what* to build; the adaptation formula tells you *how* to wire it.
