A demo of docs/canvas-as-nucleus.md

The canvas is a contract,
not a component.

Everything on this page is computed live from the running engine — the same SF.renderSlide, SF.applyRegions and SF.latticeFit the editor and the projector use. No screenshots, no figures typed in by hand. If a claim here is wrong, this page shows it wrong.

1 · One slide, three answers to "where does it go?"

The same content, same theme, same renderer. What differs is only how the arrangement is stored: nothing at all, a composition name, or a map of grid regions. This is the fork the review says has to be resolved — here it is, side by side.

2 · Which one wins when a slide has both?

A slide can carry a composition and a region map. applyRegions runs after compositions.apply, so the region map wins — and nobody decided that. It fell out of where the call was placed. The left slide has only a composition; the right has the same composition plus regions.

This is the urgent item. The precedence above is currently held by a line number in js/render.js rather than by a decision, a name or a test. Whatever the answer should be, it needs to be one of those three.

3 · Fit is counted in lines, and it says what to do

A block holds the lines its region gives it. When its content needs more, the verdict names the shortfall rather than only reporting failure. Drag the span below and watch it change — this is SF.latticeFit, the same call the Layout face makes in the editor.

Building this page found a flaw in the lattice. A region is keyed by the block's data-content-key, or by its first class if it has none. A bullet list on a content slide has neither, so it keys as block-1 — its index. A positional key is precisely what a named region is supposed to avoid: reorder the blocks and every region below the change points at the wrong one. Every block that can hold a region needs a stable name.

4 · The overwhelm, measured

The brief was a nucleus without drowning in options. These numbers are counted live by building every library pack and walking every slide, so they cannot drift from the code.

The finding. Every composition is used. Nearly half the design keys never have been. The abstraction that names a whole arrangement earns its keep; the individual knobs are the bloat — so the fix is fewer knobs, not fewer layouts.
